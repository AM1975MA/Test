# ETF_TRADER / Original149 — end-to-end data quality audit (scope and evidence, 2026-10-09)

**Disposition: NOT ALL DATA CORRECTED.** This is a source-code and retained-evidence audit, not a false assertion that all missingness across all data pipelines was measured. No production edits, no new model, no CAGR claim.

## Frozen upstream evidence
- `gap_analysis/results/yfinance_repeatability_v1/RESULT.json`: Yahoo/yfinance 0.2.66 same contract, Original149 three consecutive downloads: **137/149 OHLC CSVs differ in each pair**, no date/row mismatches, no volume differences. Maximum matched-bar OHLC relative revision 2.511053215190893e-6; max close-to-close daily return difference 3.7959142892285413e-6. All 137 changed tickers fail constant-multiplicative-rescaling classifier. Therefore original raw-vintage noise remains real and **was never corrected** by the `downvol` transformation.
- Protocol `gap_analysis/protocols/YFINANCE_REPEATABILITY_V1.md`: adjusted OHLC = Yahoo Adj Close/raw Close multiplier on OHLC; Volume remains raw. Upstream corporate action semantics, ex-dividend and split truth have NOT been independently reconciled against issuer/official source.
- `source_only/raw_io.py`: validates unique dates, positive OHLC, nonnegative volume, min Low <= Open/Close <= max High, finite bars and unique tickers. It does NOT independently verify upstream adjustments, outliers with otherwise plausible OHLC, stale/stuck prices, cross-ETF exchange calendars, zero-volume market anomalies, stale data dates, split-adjusted volume, primary-listing/inception or delisting truth.
- `source_only/kernel.py`: `download_ohlcv()` uses `auto_adjust=True`, batched `threads=True` and a separate end range versus the 3-repeat evidence pipeline; production ingestion contract therefore is **not byte-identical by design** to the frozen research acquisition contract. Avoid inferring that successful CSV validation proves production repeatability.

## Confirmed uncorrected defect propagation beyond nine columns
- Canonical `kernel.rolling_downvol(ret,h)` is `ret.where(ret<0).rolling(h,min_periods=max(10,h//2)).std(ddof=0)*sqrt(252)`, with 10 / 31 / 63 negative days required for h 21 / 63 / 126.
- Canonical `build_features` calls this shared function for COMPACT21 raw `downvol{h}`, **and separately** for tail/intermediate variables `D['downvol_21']`, `D['downvol_63']`, `D['downvol126']`; these feed percentile `_rank` aliases (including `downvol21_rank`, `downvol63_rank`, `downvol126_rank`, `downvol_21_rank`, `downvol_63_rank`) and may propagate into Tail and `build_opp_panel` as applicable. These D/Tail features were NOT changed by the COMPACT21-only `repair_downvol_family`.
- Changing COMPACT21 values alone while leaving original `Tail` and other pipelines unchanged is an intentionally isolated causal experiment, **not an end-to-end data cleaning solution**.
- `source_only/kernel.py:cs_pct` uses date-wise pandas percentile ranks, and `cs_robust_dev` uses cross-sectional median/MAD with MAD=0 -> NaN, max clipping ±8. Small Yahoo bar revisions can modify near-tied rank order or source-level zero/nonzero MAD. The remaining 116 COMPACT21 columns and other model inputs have **not** undergone a fully retained pairwise missing-mask, sign/count, sensitivity and predictive-causal audit for all dates, and have not been corrected.
- `source_only/kernel.py:add_labels` uses the next market session Open and the Open at +21/42/63 sessions; outcome maturity is enforced in model training. Labels can still be perturbed by original provider OHLC revisions and monthly per-vintage percentile rankings. Prior attribution work found differences in rounded labels, but **there is no independent price/adjustment truth audit** showing all labels are correct. Validate session alignment, corporate actions, entry/exit availability and per-vintage target coverage before any blanket approval.
- `source_only/models.py` uses feature-count eligibility `>=30`; missingness in remaining features and side models is not a simple completeness PASS when rows remain eligible. XGB missing-value branch decisions can be unstable even when only a few NaN-pattern changes occur.

## Recommended strict audit workflow, BEFORE another learner experiment
1. **Data manifest**: from the original frozen 3 raw acquisitions per ticker/date, reconcile OHLCV schema, revised bars, normalized price levels, adjusted OHLC factor and upstream corporate action/split provenance; categorize all legitimate NaNs from inception, stale dates, nontrading, incomplete lookback.
2. **All-feature census**: reconstruct *all* Compact21, Tail, opp/macro and MA3 input panels per acquisition and compare each variable's null mask, finite perturbation, quantile/median/MAD division and semantic type, with date/ticker/year slices. Trace every changed feature backward to exact raw bars and transformations. Avoid touching original artifacts.
3. **Correct only verified root causes** with causality-preserving transformations and fail-closed exceptions; distinguish missing data from structurally undefined measures, legitimate zeros, and provider errors. Record treatment, forward availability and changed eligibility, never zero-fill blanket.
4. **Unit/integration tests** on synthetic corporate actions, NaNs, 0-volume, return sign flips, rank ties, zero-MAD cross-sections, partial windows, time-zone/month boundary, off-by-one entry/exit; explicit future-append invariance and no post-signal data in predictor transforms.
5. Freeze one complete coherent source-cleaning design *before* running new XGB diagnostic with all three original frozen raw acquisitions. Compare common/native stability and mature quality including selected Top1 and per-vintage noninferiority, then only if passes run full original portfolio strategy CAGR/MaxDD/turnover and independent future validation.

**Conclusion: source data have not been corrected in every aspect.** The proven nine-column correction is useful data engineering and an invalid model promotion on its own. No production changes until comprehensive evidence and economic gates.
