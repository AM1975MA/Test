# OLC34 data-quality addendum — holiday pseudo-observations; prespecified stopping preserved

2026-11-03. **This addendum follows an initial OLC34 result preview and MUST NOT be represented as pre-outcome registration.** It is a **deterministic input-provenance repair**, not a search across model hyperparameters, trading thresholds or outcome periods. The original protocol commit remains immutable (`320d11c`). Original unfiltered VIX snapshot `OLC34_VIX_ASOF_SIGNAL.csv` (Git blob 762fe8cd591b45cae78a869e8b1541e14fc87188) is preserved for audit.

Source issue: public `datasets/finance-vix` raw VIX series includes positive CLOSE observations labelled on U.S. no-index dissemination holidays: specifically 2022-05-30, 2024-11-28 and 2025-11-27 occur as the last prior-date value for three OLC32 signal dates. Official Cboe U.S. Indices notice for 2024-11-28 explicitly states **no U.S. index values or data files on Thanksgiving**: https://cdn.cboe.com/resources/schedule_update/2024/Cboe-U-S-Indices-and-Theoretical-Options-Pricing-Service-Thanksgiving-Holiday-Reminder.pdf . Cboe holiday notice for 2022-05-30: https://cdn.cboe.com/resources/schedule_update/2022/Cboe-Holiday-Reminder-Closed-on-Monday-May-30-2022.pdf .

**Independent correction rule that does not consult ETF outcomes:** remove all dates that are not regular NYSE (XNYS) sessions, using the `exchange_calendars` library calendar for 2018–2026; this is a *conservative proxy* for Cboe VIX index dissemination, not perfect Cboe-specific certification. Then recompute the latest strictly prior VIX CLOSE and trailing 21 valid U.S. session value for **all 91 signal dates**; require as-of strictly < signal date and <=7 days. Pin and publish the recomputed table. Label `OLC34_VIX_ASOF_SIGNAL_EXCHANGE_FILTERED.csv` data as **calendar-screened mirror values, not independently certified original Cboe observations**. Do not invent an unobserved VIX value, and do not interpolate.

**Experimental interpretation:** because the first test metrics were already viewed, the calendar-corrected rerun is a **post-audit sensitivity/replay**, not a new confirmatory hypothesis. P0/P1/P2 architecture, 12+2 features, sample dates, model C=0.1, training chronology, threshold P2>=0.4 and P2−P0>=0.1, flat 20bp hypothetical costs, bootstraps and strict gates are unchanged. If results still fail, STOP. If they pass, treat as exploratory requiring a genuinely new forward sample and more robust source authentication before any promotion.

These 3 direct as-of anomalies also implicate *21-session lookback indexing* for further months, so recomputing only the three rows is inadequate. Log every changed row and the full XNYS-rejected holiday dates; keep original and filtered snapshots. Do not reinterpret historical VIX regressions as point-in-time guaranteed option prices.
